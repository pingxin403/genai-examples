# 02-llm-capability：LLM 能力边界评估器

对应文章：[《别啥都上AI！一张图看懂LLM的能力边界》](../../../GenAI/01-入门篇/02-别啥都上AI一张图看懂LLM的能力边界.md)

## 功能说明

用一个可执行的 Python 脚本演示"该不该上 AI"的量化评估流程：

- 从 5 个维度给任务打分（业务价值、可替代性、风险成本、运行成本、可评估性）
- 加权求和后按阈值输出选型建议：LLM 主导 / 混合架构 / 规则系统优先
- 支持批量评估（读取 tasks.json）和交互模式（手动输入）

## 目录结构

```
02-llm-capability/
├── README.md       # 本文件
├── app.py          # 任务评估器（命令行演示）
└── tasks.json      # 示例任务清单（客服、审批、问答等）
```

## 运行环境

- Python 3.8+
- 无第三方依赖

## 运行方式

```bash
# 批量评估内置任务
python app.py

# 交互模式：手动为你的任务打分
python app.py --interactive
```

## 预期输出

批量模式下，每个任务会输出：

```
==================================================
任务: 内容头脑风暴 / 文案初稿
==================================================
  业务价值: 8/10 (权重30%, 贡献2.4)
  可替代性(反向): 9/10 (权重20%, 贡献1.8)
  风险成本(反向): 9/10 (权重20%, 贡献1.8)
  运行成本: 7/10 (权重15%, 贡献1.1)
  可评估性: 6/10 (权重15%, 贡献0.9)
  ────────────────────────────────────────
  综合得分: 7.9
  选型建议: LLM 主导
  理由: 业务价值高、规则难替代、风险可控，建议以 LLM 为核心方案
```

## 关键工程点

1. **先选问题，再选模型** —— 任务选型比模型选型重要
2. **高规则 + 低容错任务优先规则系统** —— 不是所有场景都该上 LLM
3. **优先混合架构** —— 规则兜底 + LLM 增强，往往是最稳妥的路径
